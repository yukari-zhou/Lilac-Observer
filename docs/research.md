# Lilac-Observer 研究方法与本机接口

本文中的“第 h 日”指从最近一根有效收盘日线往后的第 h 个交易日，h 可取 1、5 或 20。盘中报价显示当前交易情况。走势图中的扇形以最近一次收盘为起点，展示期末情景。个股价格单位为元／股，指数单位为点。启动程序、添加自选股和配置模型的步骤见[使用说明](../README.md)。

## 一次研究如何生成

| 输入 | 如何进入研究 | 在哪里核对 |
| --- | --- | --- |
| 指数与个股行情 | 接收报价和已收盘日线。个股分时展示当日价格；预测和收益比较使用已确认的前复权日线 | 来源时间、行情状态、日线截止日与复权口径 |
| 指数财报 | 从权重表取前 20 大成份股，将最近可用财报的归母净利润与营收同比按 6∶4 综合。实际覆盖的指数权重参与折减 | 权重日期、覆盖率、成份股明细与披露日期 |
| 个股财报与公告 | 按交易所及代码匹配报告，区分报告期、披露日和修订日。公告提供标题与原文链接 | 个股财报明细、公告发布时点 |
| 宏观与行业 | 取制造业 PMI 水平及月度变化。行业工业增加值按可对应的分类与当前标的匹配，作为弱景气因子 | 国家统计局原文、匹配分类、适用范围 |
| 市场情绪 | 从公开快讯中提取上涨／下跌家数。只有可判定时点、范围和方向的证据才产生数值贡献 | 新闻日期、来源和广度计算口径 |

证券目录参考沪深交易所名单与公开行情目录，报价和日线使用腾讯财经、新浪财经、东方财富等来源。权重来自中证与国证指数，财报、公告和行业统计可沿界面链接回查。不同源的时间戳、更新周期与可用市场可能不同。[上交所市场数据](https://www.sse.com.cn/market/) · [深交所市场数据](https://www.szse.cn/market/) · [国证指数](https://www.cnindex.com.cn/) · [国家统计局发布](https://www.stats.gov.cn/sj/zxfb/) · [巨潮资讯](https://www.cninfo.com.cn/)

### 价格模型和证据修正

1. 至少有 60 根有效日线时，用历史漂移、20／60 日均线趋势、期限动量、量价强度和下行波动拟合滚动岭回归。目标为当时波动率标准化后的期限收益。每一预测窗口结束后，已实现收益才进入下一次拟合。
2. 按同期限的历史预测误差计算第 10 和第 90 百分位。误差不足 12 个时使用约 ±1.28 倍期限波动估计。80% 是设计的目标覆盖率，使用者可以在历史验证中查看实际覆盖率。
3. 外部证据按类别和来源汇总，再按时效、适用范围及覆盖率折减。修正幅度上限为 0.20 个期限波动单位。历史复盘还会检查数据在基准时点的可见性。报告只提供披露日期时，从次日开始使用。
4. 个股少于 60 根有效日线或复权口径待核实时，保留可用走势图。有 60 根日线但当前周期尚无合格的样本外记录时，以最近收盘为中枢，仅给出波动参考，方向显示「样本待积累」。

### 条件策略与风险线

偏强信号形成突破后分批介入的条件策略，需要至少 24 个同期限样本外窗口，同时满足方向命中率高于基准、平均绝对误差低于基准。保护距离按 14 日平均真实波幅（ATR）计算，1／5／20 日分别使用 1.25／2／3 倍，并取收盘价的 0.5% 和 0.01 个价格单位作为下限。界面给出的保护线用于收盘后复核已有多头风险。

开启复核时，模型接收该标的的数据摘要、可用证据与量化门槛，返回沿用条件策略、等待确认或降低风险的判断。网页按证据编号展示依据。模型回答可能遗漏信息或误解事件，公告和财报的关键数字应点开原文核对。证券交易时还需考虑停牌、涨跌停、跳空、交易成本与跟踪产品折溢价。

个股原有策略还会给出一笔买入、一笔卖出的成本示例，科创板用 200 股，其余用 100 股，入场以参考收盘价计算。预测区间和复核价沿用股价单位。示例的中枢及保护位净盈亏，分别用对应价格估算卖出净回款，再减去含费买入总支出。达到保本卖出报价时，该数量的预计净回款才覆盖成本。指数点位需要结合实际交易的基金或其他跟踪产品另行估算费用。

## 怎样理解「历史验证」

| 读数 | 计算口径 | 适合比较什么 |
| --- | --- | --- |
| 样本数 | 滚动训练满 12 个已兑现窗口后，统计近期同期限、互不重叠的验证窗口 | 20 日周期通常比 1 日周期样本少，可并看命中率和样本数 |
| 方向命中率 | 价格模型中枢相对基准日收盘的涨跌方向，与实际方向的一致比例 | 同一批窗口里「始终看涨」的命中率 |
| 收益 MAE | 预测收益率与实际收益率之差的绝对值，再取均值 | 以收盘持平为预测的 MAE，数值越小越好 |
| 区间覆盖率 | 到期收盘落在当时价格模型区间内的比例 | 与 80% 目标覆盖率、区间宽度一同查看 |
| 前向记录 | 本机实际生成且符合留档条件的预测，在未来到期时核验 | 新数据逐步积累后的实际表现 |

历史验证覆盖价格模型。当前财报、新闻和外部模型解释的增量效果，需要通过前向观测另行检验。个股滚动验证使用本次取得的前复权序列，分红送转后，历史价格可能重算。命中率、覆盖率与 MAE 均未计入资金管理、手续费或止损成交结果。

**前向记录何时产生？** 源端行情和收盘日线有效、复核已完成，且出具时间位于当日 15:00 到下一工作日 09:15 之前时，同一标的、基准日和周期仅留存第一份。个股还需有前复权基准和可用验证样本。下一工作日按周末规则估计，法定长假可能少收样本。下一次查看该标的和周期时，系统按实际有日线的第 h 日核验。对个股，使用同一前复权序列中的到期收盘与基准收盘之比，换算回出具预测时的价格基准。相邻日期的前向记录可能共享部分交易日。

## 个股策略复盘

在个股的「历史验证」打开「策略复盘」，可以比较同一只股票、同一批日期上的交易结果，看看加入情报或 AI 复核怎样改变净收益和回撤。每种策略使用独立的 100 万元模拟资金，与个人模拟账本无关。

### 留下哪些记录

1. **交易日收盘后保存信号。** 上海时间当天 15:00 后，保持本机服务运行并联网。程序为自选股保存当日首次符合条件的两份 5 日信号，一份仅用价格走势，一份加入当时可用的情报。它们需要同日有效的收盘行情、前复权日线和可用的验证窗口。当天已保存的信号保持原样。
2. **AI 复核按截止时点配对。** 同一份普通研究材料的合格复核，须在收盘至下一工作日 09:15 前完成并被服务收到。迟到的判断和私人持仓复核不进入这次比较。「收盘后自动请 AI 复核全部自选股」默认关闭。开启后或启用状态下重启服务时，符合条件的已存信号可在截止前立即排队，沿用原信号冻结的公开材料，每条信号最多自动调用一次模型。普通研究页面的请求独立运行。AI 策略采用每次复核时所选模型的判断，期间更换模型会影响这一行的解释。
3. **下一个工作日盘中留报价。** 在连续竞价时段再次运行服务。每股使用这段时间内本机实际采到的第一笔有效报价。各策略共用该时点的最新价和买卖盘。只有需要交易且具备对应一侧报价、可用资金和合规股数，模拟委托才可能成交。日期按周一至周五向后推算，节假日或停牌可能留下缺口。错过的信号、报价和复核均不能事后补填。

### 怎样交易和比较

| 策略 | 持仓规则 |
| --- | --- |
| 只看走势 | 5 日信号偏强且示例一买一卖在预测中枢扣费后仍盈利，目标为持股。其他情形目标为持币 |
| 走势＋情报 | 同样的持仓规则，信号还纳入当时可得的财报、市场情绪等证据 |
| 走势＋情报＋AI | 「沿用」跟随情报策略。「等待」暂缓新买入，在情报策略仍建议持有时允许保留已有仓位。「降低风险」转为持币 |
| 买入并持有 | 目标始终为持股，用作参照 |

每只股票单独计算，每个有决策的交易日最多尝试调仓一次。买入使用当前现金在单笔委托上限内可负担的最大合规股数，卖出已有持仓。买卖遵守 T+1，并使用模拟账本的对手盘、滑点、最低佣金、过户费和卖出印花税假设。示例交易的预期净盈利仅用于决定是否持股。实际净收益由后续采到的报价计算。5 日是信号的预测期限，每次收到新的合格信号都可以重新判断仓位。保护线用于单独测算风险，复盘不重建盘中止损成交。

「全部量化记录」让价格、情报和买入持有策略在相同报价上比较。「含 AI 的共同日期」要求决策日期同时有及时 AI 复核和对应报价，四种策略在这组日期上另行起算。首末共同日期之间，若某天有行情但缺少 AI 复核，四种策略当天都保留原仓，并按实采报价更新净值和回撤。两个分组的开始日期、样本量和持股路径可能不同，每组内的收益差才对应相同条件。

比较显示最近一段可连续核对的数据。若报价缺日，或记录的未复权收盘与下一工作日报价提供的昨收值缺失或不一致，两组从新观察日恢复相同初始资金。先前的报价保留，可在界面查看重新起算的原因。该规则核对前收价格基准，正常的开盘涨跌不会单独触发重算。

| 指标 | 读法 |
| --- | --- |
| 扣费后收益 | 现金加余仓按观察价估算的净卖出回款，除以初始资金再减一。已纳入交易滑点和税费，余仓也计预计卖出成本 |
| 最大回撤 | 从初始资金开始，按各观察时点的账户净值，统计从此前高点到后续低点的最大跌幅。盘中两次观察之间的波动可能更大 |
| 换手率 | 已成交的买入额与卖出额合计除以初始资金，可超过 100% |
| 税费与成交 | 税费只合计已成交委托的佣金、过户费和印花税。滑点反映在成交价中。缺少可用对手价或买不起最小买入数量时会记录未成交 |

回撤取决于实际观察日期，费率和滑点采用统一假设。盘口深度、排队、部分成交和实盘分红入账会改变结果。短区间或很少几笔成交的领先，不能说明该策略在其他时期也会领先。

## 模拟账本

模拟账本按分记录人民币金额。买入后将全部支出加入持仓成本。部分卖出按卖出股数占原持仓的比例分摊成本，清仓时全额结清。已实现盈亏为卖出净回款减去所分摊成本。浮动盈亏为市值减剩余持仓成本，预计平仓盈亏还计入退出的滑点和费用。保本、平仓和止损情景测算均假设届时可按参考价成交，当前 T+1 锁定的数量仍需待下一交易日。超过单笔市场上限的大仓在平仓测算中按上限拆单计费。不能取得有效新报价时，估值可沿用最近一次成交所记录的报价，并标注时间与来源。滑点率及费率见[模拟交易说明](../README.md)。

「若按这笔委托成交」使用同一批行情比较委托前后。现金按预计成交和费用变动，持仓市值按最新可用的未复权价格估算。个股及其行业仓位分别用对应市值除以包含现金的账户总权益。部分持仓没有行业分类时，行业占比只覆盖已知部分，实际占比可能更高。估值沿用旧报价时会提示。

保护线取自当前标的和周期最近一次可用研究，需要与报价的价格基准相符。测算先完成本次委托，再假设其余股票价格不变，将该股剩余持仓按保护线全部卖清。余仓的当前市值减去这次卖出的预计净回款，即界面上的账户预计损失，损失比例以本次委托后的账户权益为分母。已清仓的附加损失为零。报价已经触线、只有较早估值或缺少可用研究时，会提示相应状态。该情景计算了卖出滑点与费用，遇到跳空、跌停、停牌或 T+1 锁仓时，退出价格和时点仍可能改变。

## 本机 HTTP 接口

默认地址为 `http://127.0.0.1:8765`。查询返回 JSON，写入请求使用 `Content-Type: application/json`。

| 请求 | 用途 |
| --- | --- |
| `GET /api/health` | 检查本机服务状态 |
| `GET /api/catalog` | 查看指数、自选股与默认标的 |
| `GET /api/search?q=600519` | 取得匹配的证券及交易所 ID |
| `POST /api/watchlist` | JSON 示例 `{"id":"sh600519","action":"add"}`。将操作改为 `remove` 可移除 |
| `GET /api/quotes` | 批量读取指数和自选股报价及来源时间 |
| `GET /api/research?index=sh000300&horizon=5` | 读取行情、证据、量化与前向验证结果，并触发所选模型的异步复核。股票须先加入自选 |
| `GET /api/review?index=sh000300&horizon=5` | 轻量查询对应标的与周期的复核状态。旧接口 `/api/astra` 保持兼容 |
| `GET /api/replay?symbol=sh600519` | 读取自选股已记录的 5 日策略复盘。`signals`、`pending`、`missed` 分别为累计收盘信号数、待报价数和已错过的报价数。`paired` 和 `common` 分别为当前连续区间上的量化比较和含 AI 的共同日期比较。`segment_start`、`restart_reason` 和 `earlier_samples` 给出区间起点、重新起算原因和此前保留的报价数 |
| `POST /api/replay/settings` | 传入 `{"auto_ai":true}` 开启整份自选股的收盘复核，传入 `false` 关闭。偏好保存在本机，首次默认关闭 |
| `GET /api/settings` | 查看已选服务、模型及密钥配置状态 |
| `POST /api/settings` | 保存模型设置。例如 `{"provider":"off"}`，或 `{"provider":"api","base_url":"http://127.0.0.1:11434/v1","api_model":"本机已安装的模型ID"}` |
| `GET /api/paper?symbol=sh600519` | 查询虚拟账户、持仓、近期成交、该股报价和当前能否模拟成交 |
| `POST /api/paper/preview` | 传入 `{"symbol":"sh600519","side":"buy","quantity":100,"horizon":5}`。`horizon` 可取 1、5、20，省略时取 5。卖出时将 `side` 设为 `sell`。`preview` 为含费委托，`risk` 为仓位与保护线情景，`can_trade` 表示当时能否模拟成交 |
| `POST /api/paper/orders` | 核对预览后，在同一组标的、方向和数量上附上唯一的 `request_id` 与 `expected_price`。后者取自 `preview.quote_price`。提交时服务端重新校验实时报价和资金券余额，重复提交同一编号及交易参数返回原成交 |
| `POST /api/paper/review` | 主动请求仓位复核，示例 `{"symbol":"sh600519","horizon":5,"lang":"en"}`。仅在此操作时将当前股的模拟摘要加入模型输入 |
| `GET /api/paper/review?symbol=sh600519&horizon=5&lang=en` | 查询对应语言、标的和周期的仓位复核进度。一次模拟成交后，需重新请求仓位复核 |

研究和普通复核查询也支持 `lang=en`，默认为 `zh`。历史验证统计价格预测的方向、误差与覆盖率。模拟交易的税费、个人资金和持仓复核分别进入模拟账本和仓位建议，不纳入历史预测的命中率或前向记录。

`risk` 的金额单位为元，`weight_after_pct`、`sector_after_pct`、`stop_loss_pct` 等百分比字段用 1.0 表示 1%。`stop_loss` 是余仓在保护线卖出的预计追加损失，正值代表亏损。`sellable_after`、`locked_after` 的单位为股。资料不足时，相应数值为 `null`。复盘表中的 `net_return`、`max_drawdown` 和 `turnover` 用 0.01 表示 1%。

返回值中，`analysis.interval.return_base`、`validation.mae` 等收益率字段以小数表示，0.01 即 1%。`market.quote.change_pct` 以及财报中的 `revenue_yoy`、`profit_yoy` 已乘 100，1.0 即 1%。`review` 是当前复核对象，在异步完成前请查看其 `status`。页面启用自动刷新且处于可见状态时，会轮询报价和研究结果。关闭页面会停止页面轮询。

## 配置兼容

程序仍读取 `HENGJIAN_*`、`ASTRA_MODEL`、`ASTRA_CACHE_DIR`、`ASTRA_OFFLINE` 和 `ASTRA_ENABLED`。同一项同时设置多个变量时，优先读取 `LILAC_OBSERVER_*`。API 密钥仅在对应的服务地址上使用。

Existing installations can keep the environment variables listed above. When both forms are set, the corresponding `LILAC_OBSERVER_*` value takes precedence. API keys apply only to their configured endpoint.

## 开发与测试

入口在 `app.py`，静态界面在 `web/`。行情采集在 `sources.py` 和 `stocks.py`，指数及公司财报在 `fundamentals.py` 和 `stock_fundamentals.py`，数值模型在 `engine.py`，配置和模型适配在 `llm_config.py`、`astra.py`，预测前向核验在 `forward.py`。个股策略复盘在 `replay.py`，委托预览和含费成交在 `paper_service.py`、`paper.py` 和 `trading_costs.py`。

首次通过启动脚本建立虚拟环境后，从仓库根目录运行回归测试。

```powershell
# Windows
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

```sh
# macOS / Linux
.venv/bin/python -m unittest discover -s tests -v
```
